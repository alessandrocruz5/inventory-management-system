## Decisions
- **Migrate and seed are Api run modes** (user's pick). `Program.cs` builds the app as usual. If `args[0]` is `migrate` or `seed`, it runs that command and returns before `app.Run()`.
  - The AppHost runs three resources from `Projects.Api`: `migrate` (with `args: migrate`, and `WithReference(db)`, which gives it the server admin) → `seed` (with `args: seed`, and `ConnectionStrings:inventory` as `inventory_app`) → `api` (`inventory_app`).
  - Each waits on the previous one with `WaitForCompletion`.
  - This amends the S1 Downstream note "resources are sql, api and web" to sql, migrate, seed, api, web; the ticket step rewrites it.
- **Every process reads one connection name, `ConnectionStrings:inventory`.** Only the AppHost decides which principal it carries.
  - `api` loses `WithReference(db)`. Today that reference hands it `sa`; see the Blast radius.
  - The `inventory_app` string is `builder.AddConnectionString("inventory-app", ReferenceExpression.Create($"Server={sql.Resource.Host},{sql.Resource.Port};Database=inventory;User ID=inventory_app;Password={appPassword};TrustServerCertificate=true"))`, passed with `WithReference(appConn, "inventory")`.
- **Modules expose migrate and seed through Kernel interfaces**, so T12's exact public surface (`Add<M>Module`, `Map<M>Endpoints`) stays unchanged.
  - Kernel interfaces: `IModuleMigrator { Task MigrateAsync(CancellationToken) }` and `IDataSeeder { Task SeedAsync(CancellationToken) }`.
  - Implementations are internal and registered by `Add<M>Module`.
  - Api resolves `IEnumerable<IModuleMigrator>` in registration order: Platform first, because its first migration turns RCSI on.
- **`inventory_app` is created by Api's migrate command, after all migrations** (`src/Api/Setup/DatabasePrincipals.cs`).
  - It uses `Microsoft.Data.SqlClient` (available transitively through EF) on the admin connection string, because it's server-level DDL with no tenant.
  - The password is passed as a parameter and quoted inside T-SQL with `QUOTENAME(@p, '''')` in dynamic SQL, never concatenated in C#.
  - `CREATE LOGIN` if missing, else `ALTER LOGIN … WITH PASSWORD` (so a rotated parameter takes effect). Then `CREATE USER … FOR LOGIN` if missing.
  - Grants are at schema level: `GRANT SELECT, INSERT, UPDATE ON SCHEMA::platform|identity|inventory` and `GRANT DELETE ON SCHEMA::identity`.
- **RCSI is its own first Platform migration, `EnableReadCommittedSnapshot`**, run as `migrationBuilder.Sql("ALTER DATABASE CURRENT SET READ_COMMITTED_SNAPSHOT ON WITH ROLLBACK IMMEDIATE;", suppressTransaction: true)`. Its `Down` turns it off the same way.
- **Two DbContexts, each with its own migrations and history table.**
  - `PlatformDbContext : IdentityDbContext<AppUser, IdentityRole<Guid>, Guid>`: default schema `identity`, `Tenants` in `platform`, history table `platform.__EFMigrationsHistory`.
  - `InventoryDbContext`: schema `inventory`, history table `inventory.__EFMigrationsHistory`.
  - Migrations go in `Persistence/Migrations` (namespaces `Platform.Persistence.Migrations` and `Inventory.Persistence.Migrations`), so T12's `.Migrations` exemption covers them.
  - Each context has an internal `IDesignTimeDbContextFactory` with a placeholder connection string. `dotnet ef migrations add` never connects, and the startup project is `src/Api`, which holds `Microsoft.EntityFrameworkCore.Design` with `PrivateAssets=all`.
- **Contexts are registered with `AddDbContext` + `EnrichSqlServerDbContext<T>()`**, never `AddSqlServerDbContext` (§8 `:492`, pooling).
- **No cross-schema FK from `inventory.Locations.TenantId` to `platform.Tenants`.** Modules own their schemas and their migration sets are independent. §5's "composite FKs" rule is about tenant-owned tables pointing at each other.
- **S2's `Locations` has `TenantId` as a plain NOT NULL column.**
  - The `SESSION_CONTEXT` column default, the SaveChanges interceptor, the named query filters and RLS are S3 (§12 `:668`). S3's spec explicitly covers "the tables so far".
  - Until then, `ProvisionTenantAsync` sets `TenantId` from `ITenantContext` itself and filters by it explicitly. S3 removes both.
- **Identity configuration:**
  - `AddIdentityCore<AppUser>().AddRoles<IdentityRole<Guid>>().AddEntityFrameworkStores<PlatformDbContext>().AddSignInManager().AddClaimsPrincipalFactory<TenantClaimsPrincipalFactory>()`, plus `AddAuthentication(IdentityConstants.ApplicationScheme).AddIdentityCookies()`.
  - Lockout: `MaxFailedAccessAttempts = 5`, `DefaultLockoutTimeSpan = 15 min`, `AllowedForNewUsers = true`, and `PasswordSignInAsync(…, lockoutOnFailure: true)`.
  - `RequireUniqueEmail = true`, and `UserName = Email`.
  - Cookie: `HttpOnly`, `SecurePolicy = Always`, `SameSite = Strict`, `ExpireTimeSpan = 8h`, `SlidingExpiration = true`.
  - `OnRedirectToLogin` → `401` and `OnRedirectToAccessDenied` → `403`, so there's never a `302`.
- **The `tenant_id` claim name is a Kernel constant** (`Kernel.Tenancy.TenantClaims.TenantId = "tenant_id"`). `Platform.Identity`'s claims factory writes it and Api's middleware reads it, so neither hard-codes the string.
- **The pipeline is `UseAuthentication` → `TenantMiddleware` → `UseAuthorization`.** The `/api` group calls `RequireAuthorization()`; login calls `AllowAnonymous()`. `/health` and `/alive` stay outside the group.
- **Login failures are one response:** `401` with `type: /problems/invalid-credentials` and the detail "Email or password is incorrect. After 5 failed attempts the account is locked for 15 minutes." It's the same for a wrong password, an unknown email, a locked account and `NotAllowed`. This meets §10's "lockout message" without the enumeration risk from audit `:39`. A body with an empty field gets `400 /problems/validation` with `errors`.
- **Kernel's problem slugs grow per slice.** S2 adds `Kernel.Problems.ProblemTypes` with `Validation = "validation"` and `InvalidCredentials = "invalid-credentials"`, and the Angular interceptor's map has exactly those two plus a default (Hidden coupling).
- **Seed** (`Platform.Seeding.PlatformSeeder : IDataSeeder`):
  - Tenants: demo `Demo Retail` with id `00000000-0000-0000-0000-00000000d001`, and isolation `Isolation Tenant` with id `00000000-0000-0000-0000-00000000d002`. Both Guids are constants in the seeder.
  - Users: `admin@demo.test` (Admin), `staff@demo.test` (Staff), `admin@isolation.test`, `staff@isolation.test`.
  - The password for all four comes from config `Seed:Password`, an Aspire secret parameter `seed-password` that the AppHost generates and persists in its user-secrets.
  - Idempotency: a tenant is looked up by id, a user by email (an existing user is left alone, including its password), a role by name, and locations by `ProvisionTenantAsync`.
  - Tenant creation is `Platform.Tenants.TenantProvisioner.CreateAsync(id, name)`: insert the tenant if missing, then `BeginScope(id)` and call `IInventoryModule.ProvisionTenantAsync`. Integration tests reuse it to make their own tenants.
- **`ITenantScopeFactory.BeginScope(Guid)` returns `ITenantScope : IAsyncDisposable { IServiceProvider Services }`.** Kernel has no DI-abstractions dependency, and `IServiceProvider` is `System`. Api's `TenantScopeFactory` (a singleton over `IServiceScopeFactory`) creates an async scope and sets its `TenantContext` once; the setter throws on a second set.
- **The dev proxy is `web/proxy.conf.js`**, mapping `/api` to `process.env['services__api__http__0']`, set as `serve.options.proxyConfig` in `angular.json`.
- **Angular Material arrives in S2**, through `ng add @angular/material` (allowed list) at the version pinned in Context used. It's used for the shell toolbar and the login form.
- **The shell's landing route is a placeholder `HomeComponent`** ("Signed in to {tenant}"). S7 replaces it with `/stock`, so S2 builds no nav links to screens that don't exist yet.

**Assumptions:** (for `/audit-plan` to challenge)
- **.NET 10's `Microsoft.AspNetCore.App` source generator emits `public partial class Program`** for top-level statements, so `WebApplicationFactory<Program>` works without an explicit declaration **\[Likely\]**. Prompt 08 adds `public partial class Program;` only if the build says otherwise. That would widen Api, which T12 doesn't police.
- **Browsers accept a `Secure` cookie on `http://localhost:4200`**, because localhost is a secure context in Chrome and Firefox **\[Likely\]**. In tests, `WebApplicationFactory` clients use `BaseAddress = https://localhost` so `CookieContainer` sends the cookie.
- **EF tools find an `internal` `IDesignTimeDbContextFactory`** in the target project **\[Likely\]**. If they don't, the prompt stops and reports instead of making the factory public.
- **NetArchTest doesn't flag `PlatformDbContext` (outside `Platform.Identity`) for `System.Security.Claims`** just because it derives from `IdentityDbContext<…>` **\[Likely\]**. If T12 fails, move the type into `Platform.Identity`, but never edit T12.
- **`Locations.CreatedBy` is nullable (null means system-provisioned)**, because virtual locations are created before any user exists. `UpdatedAt`/`UpdatedBy` are nullable until the first edit. §5 leaves these types unstated.
- **The seed's emails and tenant names are placeholders that S4 can rename.** The fixed ids are what make it idempotent.
- **Sliding expiration covers "8-hour sliding"**, and there's no absolute session cap in sprint 1.
- **Migration history tables live in the module schemas**, so `inventory_app`'s schema grant can write them. That's harmless, and a separate schema would add ceremony for no sprint-1 gain.
