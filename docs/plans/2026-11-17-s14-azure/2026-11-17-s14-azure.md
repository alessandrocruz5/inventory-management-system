## Decisions
- **D1** Provision with hand-written Bicep at `deploy/azure/main.bicep`, deployed by `deploy/azure/deploy.sh` through the az CLI. No Aspire Azure packages. `src/AppHost/**` and `deploy/docker-compose.yaml` stay unchanged, so S13's publish doesn't need re-running. User-approved 2026-11-17.
- **D2** `web` is S13's nginx image (`web/Dockerfile`) running as Container App `web`, with external HTTPS ingress. `api` is Container App `api`, with **internal** ingress only, `allowInsecure: true` (plain HTTP inside the environment; otherwise HTTP is redirected to an `https://api` the browser can't reach) and target port 8080. nginx proxies `/api/` to `http://api`. Static Web Apps isn't used. User-approved 2026-11-17.
- **D3** Persist Data Protection keys with `Microsoft.AspNetCore.DataProtection.EntityFrameworkCore` 10.0.14 (the same patch as the other ASP.NET/EF packages). `PlatformDbContext` implements `IDataProtectionKeyContext`. The table is `platform.DataProtectionKeys`, added in a new Platform migration. `AddDataProtection().SetApplicationName("inventory").PersistKeysToDbContext<PlatformDbContext>()`. `inventory_app` already has `SELECT, INSERT` on `platform`, and the store never updates or deletes, so the grants don't change. CLAUDE.md's allowed list records the package. User-approved 2026-11-17.
- **D4** Images go to public GHCR: `ghcr.io/<owner>/inventory-api:<tag>` (one image for `migrate`, `seed` and `api`; the run mode is the container arg) and `ghcr.io/<owner>/inventory-web:<tag>`. The tag defaults to `git rev-parse --short=12 HEAD`. The API image is built with the SDK's `dotnet publish -t:PublishContainer`; `web` uses `docker build web`. User-approved 2026-11-17.
- **D5** `DatabasePrincipals` creates a **contained** database user, `CREATE USER [inventory_app] WITH PASSWORD = …` (or `ALTER USER … WITH PASSWORD` when it exists), when the database is Azure SQL Database (`SERVERPROPERTY('EngineEdition') = 5`) or partially contained (`sys.databases.containment = 1`). Otherwise it keeps today's login path unchanged. The grants and DENYs are identical in both paths. The branch is decided in C# with two queries, so the `containment` column is never compiled on Azure SQL. A test on a partially contained database on the Testcontainers server covers the contained path.
- **D6** Azure SQL uses SQL authentication. The server admin login (parameter `sqlAdminLogin`, never `sa`) is used only by the `migrate` job, mirroring `sa` in compose. Entra-only authentication stays off, because a contained user with a password needs SQL auth. Entra ID is a non-goal (spec §14: Entra later).
- **D7** `migrate` and `seed` are Container Apps **Jobs** with a manual trigger, `replicaRetryLimit: 0` and `replicaTimeout: 900`. `deploy.sh` starts `migrate`, waits for `Succeeded`, then does the same for `seed`, then warms up `GET /api/auth/me` (expects 401). Container Apps has no start order, so the script is the ordering.
- **D8** nginx forwards `Host $proxy_host` (the upstream's own name) and `X-Forwarded-Host $host`, and sets `proxy_read_timeout 120s`, because a cold api plus a paused database can take more than nginx's default of 60 s. In compose the API now sees `Host: api:8080`. The API never reads Host: `Location` headers are relative, and `AllowedHosts` is `*`.
- **D9** `tests/e2e/playwright.config.ts` reads an optional `E2E_BASE_URL`. When it's set, `baseURL` uses it and `webServer` is omitted. CI and local runs without it are unchanged.
- **D10** Cost guardrails in Bicep: the SQL free offer with `AutoPause`; `api` and `web` on min 0 / max 1 replicas; a Log Analytics workspace with 30-day retention and `dailyQuotaGb: 1`; no ACR, no Static Web Apps, no VNet. The README carries a cost table and the teardown command, `az group delete`.
- **D11** The Azure SQL firewall has one rule, `AllowAllWindowsAzureIps` (0.0.0.0). Consumption Container Apps have no fixed egress IP, and a private endpoint needs a VNet (cost). Mitigations: TLS 1.2 minimum, `Encrypt=True`, generated passwords of 24+ characters, and an admin credential held only by the `migrate` job's secrets.
- **D12** Units: **IMS-20** (new ticket) "Persistent sign-in keys and contained SQL user", prompts 01–02, high-stakes (Identity + Migrations), so code-guardian applies. **IMS-18** "S14 Azure", prompts 03–05, depends on IMS-20. IMS-20 ships alone and helps compose too. IMS-18 is IaC, nginx and docs, and matches no high-stakes glob.
- **D13** Model: IMS-18's provisional `sonnet` becomes `opus` for prompt 04 (see Prompts), so the TASKS line's `model:` becomes `opus`.
- **D14** (Codex audit BLOCK, user-approved 2026-11-17) Azure SQL Database allows `SET READ_COMMITTED_SNAPSHOT` only from `master`, and EF migrates inside `inventory`. So prompt 02 guards the already-applied migration `20261104105221_EnableReadCommittedSnapshot`'s `Up`:
  - When `is_read_committed_snapshot_on` is already 1, it does nothing.
  - On Azure (`EngineEdition = 5`) with RCSI off, it `THROW`s with a clear message.
  - Otherwise it runs the original `ALTER` through `EXEC`.
  - Azure turns RCSI on by default, so the first Azure `migrate` passes. Its success proves RCSI is on, which is what prompt 05 checks.
  - EF tracks migration ids, not bodies, so databases that already applied it are untouched. A fresh SQL Server database still runs the `ALTER` (`Read_committed_snapshot_is_on`, and prompt 02's contained test).
  - `Down` is unchanged: rolling back on Azure is a non-goal.
  - Rejected: making `MigrateCommand` pre-insert the history row (it hides schema intent) and connecting to `master` from the migrate job (it needs a second connection string, and EF can't switch databases on Azure).
- **D15** (Codex audit FIX, user-approved alternative 2026-11-17) Prompt 01 had 9 files. The README "Known limits" line and the CLAUDE.md allowed-package entry move to prompt 02, which is in the same unit IMS-20. Codex proposed moving them to prompt 05 instead. That was rejected, because IMS-20 would then ship a new package without its allowed-list entry and with a stale README, and IMS-18 is stretch and may never merge. Prompt 01 now has 7 files, 3 of them generated by one `dotnet ef migrations add`. Prompt 02 has 5.

**Assumptions:**
- The user has an Azure subscription whose one free-offer database is unused, installs the az CLI, and runs `az login` before prompt 05's deploy step. Build agents never log in to Azure.
- The region is `southeastasia` (Singapore, the nearest to the Philippines), and Container Apps and the SQL free offer are available there. Data is demo data only, so Data Privacy Act cross-border rules don't apply yet. The README says so.
- A new Azure SQL database has RCSI on by default **[Likely, documented]**, so D14's guard skips the `ALTER`. If someone has turned it off, `migrate` throws a clear message, and prompt 05 stops and reports. The fix is a one-line `ALTER DATABASE` from `master`, which the user runs.
- `http://api` from `web` reaches the internal-ingress `api` through the environment's Envoy when the Host header is `api` **[Likely, documented by name-based calls]**. Prompt 05's contingency: proxy to `https://api.internal.<defaultDomain>` with `proxy_ssl_server_name on`. That is an env value change in Bicep only.
- When the api scales from zero, the request that triggers it is held, not dropped, and the first request after idle can take up to ~60 s (database resume). `Connection Timeout=60` in the connection strings plus EF's retrying strategy (`EnrichSqlServerDbContext`) absorb error 40613.
- A redeploy briefly runs the new `api` image before the `migrate` job applies a new migration. That's acceptable for a demo, and the README notes it.
- GHCR packages start private. The user makes `inventory-api` and `inventory-web` public once, after the first push, or the Container Apps can't pull them.
- Data Protection keys are stored unencrypted in `platform.DataProtectionKeys` (TDE covers rest on Azure). `inventory_app` can read them, as it can already read `identity.*`. Encrypting them with Key Vault is a non-goal.
- `migrate` and `seed` also register Data Protection, because `AddPlatformModule` runs in every mode. It is lazy and creates no key unless something protects data.

**Non-goals:**
- Static Web Apps; ACR; Aspire Azure packages; any change to `src/AppHost/**` or `deploy/docker-compose.yaml`.
- CI/CD deployment, a CI job for Bicep, GitHub OIDC to Azure.
- Custom domain, VNet, private endpoint, Key Vault, Entra ID authentication, OpenTelemetry export to Azure Monitor, more than 1 replica, backups beyond Azure SQL's default point-in-time restore.
- Fixing the IMS-19 `[~]` ledger line; `TASKS.md`, `CHANGELOG.md` or `docs/plans/**` inside a PR.
