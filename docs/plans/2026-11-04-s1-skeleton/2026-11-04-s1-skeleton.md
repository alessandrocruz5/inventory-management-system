## Decisions
- **Plan against `main` at baca633.** The user switched to `main`, and IMS-2 is at the same commit.
- **Protect `main` with a repository ruleset, with admin bypass** (user's pick).
  - Rules: require a PR (0 approvals; solo developer), require the `build` and `test` checks from GitHub Actions (not strict up-to-date), block force-push and deletion.
  - Bypass: the Repository admin role, bypass mode `always`, so the workflow's direct-to-`main` ledger pushes still work and each bypass is logged.
  - The user runs it after the merge (see Post-merge). build-unit doesn't, because it's an outward-facing repo setting.
- **Remove `AspireUseCliBundle` from the AppHost csproj.** The template sets it to `true`, which skips the DCP and Dashboard NuGet references. `dotnet run --project src/AppHost` would then fail without the Aspire CLI, breaking §13's fresh-clone check and CI.
- **Tests run on Microsoft Testing Platform.**
  - `global.json` sets `"test": { "runner": "Microsoft.Testing.Platform" }`, and each test project references `xunit.v3` only. That is the allowed package name; it pins `xunit.v3.mtp-v2`.
  - No `Microsoft.NET.Test.Sdk` or `xunit.runner.visualstudio`, which aren't on the allowed list.
  - `global.json` also pins SDK `10.0.112` with `rollForward: latestFeature`, and CI reads it.
- **Module registration classes are `InventoryModuleExtensions` and `PlatformModuleExtensions`.**
  - Signatures: `IHostApplicationBuilder Add<M>Module(this IHostApplicationBuilder)` and `IEndpointRouteBuilder Map<M>Endpoints(this IEndpointRouteBuilder)`.
  - Using `IHostApplicationBuilder` means S2 can call Aspire's `EnrichSqlServerDbContext` (§8 `:492`) without a signature change.
  - The `…Extensions` suffix leaves the name `InventoryModule` free for S2's `IInventoryModule` implementation.
- **Architecture.Tests comes right after the module projects** (prompt 02), so every later prompt runs `dotnet test` against real tests.
- **T12 in S1 has four rule groups:**
  - Module public surface.
  - Inventory.Domain purity.
  - Kernel purity.
  - No claims reading in modules, plus project-reference rules from csproj parsing.

  The Domain and Kernel rules have no types to check until S2 and S5b. Prompt 02's Done-when injects temporary violations to prove that each rule fails.
- **S1 creates only `Architecture.Tests`.** The other test projects arrive with their first tests. Under MTP a test project with zero tests fails `dotnet test` **\[Likely\]**.
- **`web` listens on fixed port 4200** through the Aspire endpoint (`port: 4200, env: "PORT"`). That's the Angular convention, and S12's Playwright `baseURL` can rely on it.
- **No `opus` prompts.** No High-stakes glob is touched: `Domain/`, `Persistence/`, `Features/`, `Migrations/`, and `Auth*`/`Tenant*` all stay empty. The `Shared code:` globs get empty csproj files only, with no symbols and no dependents.
- **Pre-build:** the CLAUDE.md and spec edits aren't bookkeeping. They must be on `main` before `/build-unit`, or its clean-tree check fails.

**Downstream (locked by S1; add to TASKS.md at the ticket step):**
- Every test project references `xunit.v3` only, has `<OutputType>Exe</OutputType>`, and runs under MTP via `global.json`. Create a test project together with its first test.
- `Inventory.Domain` may depend only on `System.*` (not `System.Data`), itself and `Kernel`.
- `Kernel` never depends on EF Core, ASP.NET Core, SqlClient or `System.Data`. In practice, the "ProblemDetails types" in Kernel are slug constants or exception types, and Api maps them to ASP.NET `ProblemDetails`.
- Module implementation projects expose exactly one public type, `<M>ModuleExtensions`; everything else is `internal`, and test projects get `InternalsVisibleTo`. If a slice must widen the surface, it edits T12 in the same PR and says why.
- In Platform, only the `Platform.Identity` namespace may touch `System.Security.Claims`, which matches the `src/Modules/Platform/**/Identity/**` High-stakes glob.
- Only `src/Api` and `tests/**` may reference a module implementation project. A module may reference another module's `.Contracts` (S2: Platform → Inventory.Contracts).
- S2 wires the dev proxy `/api` → `services__api__http__0` (web already holds the api reference), uses `ConnectionStrings:inventory`, and adds the `inventory_app` password parameter to the AppHost.
- S12 adds `e2e` to the ruleset's required checks. Job ids are the check contexts.

**Assumptions:** (for `/audit-plan` to challenge)
- **Domain may use Kernel's pure helpers** (§4 puts Money/Quantity helpers in Kernel). T12 keeps Kernel free of EF/ASP.NET/SQL, so this doesn't weaken "Domain is pure C#". The audit's "BCL only" wording would force rounding helpers into Domain instead.

- **Angular uses SCSS** (Material theming arrives in S2+), with no SSR and with routing. The generated welcome page stays until S2's app shell replaces it.
- **The Api baseline includes `AddProblemDetails` + `UseExceptionHandler` + `UseStatusCodePages`, and dev-only OpenAPI + Scalar.** These trace to CLAUDE.md's Stack row and its ProblemDetails convention, and they add no package beyond the allowed list.
