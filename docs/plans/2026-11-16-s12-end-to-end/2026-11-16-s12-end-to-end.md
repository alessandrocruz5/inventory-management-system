## Decisions
- **D1 Stack start (user: option A).** `playwright.config.ts`'s `webServer` runs `dotnet run --project ../../src/AppHost --launch-profile http` with `ASPIRE_ALLOW_UNSECURED_TRANSPORT=true`. It waits on `http://localhost:4200/api/auth/me`, which Playwright counts as ready on a 401, so the proxy and the API are both up. `web` already waits for `api`, which waits for `seed`. `reuseExistingServer: !process.env.CI`. Timeout: 15 minutes (cold image pull plus the first `ng serve` compile).
- **D2 Test data (user: fresh location + CANDLE-WHT).** Each test that posts creates its own physical location as Admin, then posts the seeded, stockless `CANDLE-WHT` there. `/stock` filtered to that location then shows exactly one row, so T14's absolute numbers hold on a reused local database, and the location never competes with the 25-row page. The location is created with an in-browser `fetch('/api/locations')` after the Admin signs in through the UI. That way the `Secure`, `SameSite=Strict` cookie behaves exactly as it does for the app, and no APIRequestContext cookie-jar behaviour is involved. Code: `E2E-` + base36 of `Number.MAX_SAFE_INTEGER - Date.now()` + 2 random chars. The newest code sorts first in the 100-row location lists (`ORDER BY Code` after physical-first), so local reruns never push it off the list.
- **D3 Suite scope (user).** T14 (R2), the ledger page as Admin and Staff (R3, IMS-15 Downstream), and the 375 px receipt (R4, §13). The negative-stock toggle is left out: T15 covers it at the API.
- **D4 Banned check (user: build step, transitive).** `.github/scripts/check-banned-packages.sh` (bash 3.2-compatible + `jq`) runs as the last step of `build`, which is already a required check. It covers .NET `topLevelPackages` and `transitivePackages` from `dotnet list InventorySystem.slnx package --include-transitive --format json`; ids matching `^(MediatR|AutoMapper|MassTransit)($|\.)` (case-insensitive) and `FluentAssertions` with major ≥ 8. For npm, it reads every `git ls-files '*package-lock.json'`, matching keys ending `node_modules/primeng` or `node_modules/@primeng/<x>`. The lockfile is stricter than the spec's "grep `package.json`" and still covers direct dependencies. It fails closed on input it can't trust: a project with no `frameworks` (not restored), or a lockfile without `packages` (lockfile v1). Optional `--dotnet-json FILE` and lockfile arguments exist only so a fixture can prove it fails.
- **D5 Credentials.** Users are the seeded `staff@demo.test` and `admin@demo.test`. The password comes only from `E2E_PASSWORD`. When it's set, the config also passes it to the AppHost it launches as `Parameters__seed-password`, so the seed and the tests agree. CI generates a fresh value per run (`E2e!` + 32 hex + `Aa9`: every class that Identity's default policy and the parameter's `Min*` need), masks it with `::add-mask::`, and exports it through `$GITHUB_ENV`. Locally, the README reads it from `dotnet user-secrets list --project src/AppHost` into the variable without echoing it. Tests throw a clear error when it's missing. `playwright test --list` works without it.
- **D6 Package layout.** `tests/e2e` is its own npm package (spec §4) with only `@playwright/test` (exact version from `npm view @playwright/test version` at build time), with no TypeScript or ESLint dependency: Playwright transpiles the specs. It isn't in `## Commands`, because it needs an x64 Docker host (the S8 Log shows SQL 2025 can't run on this arm64 Mac). CI `e2e` is its gate.
- **D7 Honest signal.** `workers: 1`, `fullyParallel: false` (the tests share the demo tenant, and a rebuild must not interleave a posting assertion), `retries: 0`, `forbidOnly` in CI, `trace: 'retain-on-failure'`, `screenshot: 'only-on-failure'`, reporters `list` + `html` (`open: 'never'`) in CI. Artifact: `playwright-report/` and `test-results/` on `failure()`, kept 14 days.
- **D8 Selectors.** Use role and label locators that match what a user sees: `getByLabel`, `getByRole('combobox' | 'option' | 'button' | 'link' | 'dialog')`. For AG Grid cells, use `getByRole('row').filter({ hasText: 'CANDLE-WHT' })` then `[col-id="onHand" | "averageCost" | "stockValue"]`. Expected texts come from `format.ts`: `7`, `10`, `₱100.00`, `₱700.00`, `₱1,000.00`.
- **D9 CI job.** `e2e`: `needs: test` (spec's `build` → `test` → `e2e`), `ubuntu-latest`, `timeout-minutes: 30`, the same pinned actions as the other jobs, plus `dotnet dev-certs https` (in case Aspire picks up an https endpoint), `npm ci` in `web` and `tests/e2e`, `npx playwright install --with-deps chromium`, `npx playwright test`, and `actions/upload-artifact` at its current major (resolved at build time).
- **D10 No product code.** The unit changes no `src/**` or `web/src/**` file. If T14, the ledger test or the 375 px test exposes an app bug, the prompt stops and reports it (a hotfix or follow-up), and never edits the app to make a test pass.
- **D11 Review gate.** S12 isn't in CLAUDE.md's code-guardian list and touches no `## High-stakes paths` glob, so the PR uses the standard Codex review only.
- **D12 Required check (R7).** After the PR's `e2e` run is green, the user adds the `e2e` context to `main`'s ruleset (Settings → Rules → the `main` ruleset → Require status checks → add `e2e`). The plan's Done list carries it, and nothing in the unit automates it.

**Assumptions:**
- On `ubuntu-latest`, the AppHost's `http` profile with `ASPIRE_ALLOW_UNSECURED_TRANSPORT=true` starts headless, and `api` serves the http endpoint the proxy reads (`services__api__http__0`). The `dotnet dev-certs https` step covers Aspire picking an https launch profile for `api`.
- Chromium keeps the `Secure` cookie on `http://localhost` (it's a secure context). The dev flow already depends on this.
- Playwright merges `webServer.env` over `process.env`, and the AppHost's configuration reads environment variables after user secrets, so `Parameters__seed-password` wins over a persisted value.
- The `seed` step only creates missing users: on a reused local database, `E2E_PASSWORD` must be the persisted `seed-password` (the README says so). In CI the database is new on every run.
- Aspire's `web` resource runs `npm start` in a `web/` that CI has already `npm ci`'d.
- A cold SQL 2025 pull, migrate, seed, `api` and the first `ng serve` compile fit in 15 minutes on `ubuntu-latest`.
- On the desktop, `/stock`'s `mat-select` and the post-stock `Item` autocomplete expose the accessible names `Location` and `Item` (Material links `mat-label` through `aria-labelledby`). If one doesn't, the prompt changes the selector, not the app.
- On a reused local database, every run leaves two `E2E-…` locations holding `CANDLE-WHT` stock (no hard deletes; they can't be deactivated while they hold stock). This is accepted and documented in the README. CI's database is thrown away.

**Non-goals:** any change under `src/**` or `web/src/**`; Firefox or WebKit; visual or screenshot regression; a negative-stock toggle e2e; `Aspire.Hosting.Testing` or Playwright for .NET; adding e2e to `## Commands`; Docker Compose (S13); changing GitHub settings (R7 is the user's step); `TASKS.md`, `CHANGELOG.md` or `docs/plans/**` inside the PR; the IMS-19 ledger line still showing `[~]` although `c25bc245` merged it (bookkeeping, outside this unit).
